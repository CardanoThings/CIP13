# Ecosystem

The upstream state this tracker reports on: what each `web+cardano` link type's CIP says, and what wallets actually do. Every fact has the date it was checked and where it came from. When you re-check something, update the date; when something is out of date, fix it here first and then in the site.

This file records spec and test facts only. It does not promote any wallet, dApp or project, including ones the maintainers work on.

Last full pass: 2026-11-21, against `cardano-foundation/CIPs` and the public source of Yoroi, Lace and Daedalus.

## Where the work happens

- [CIPs#836](https://github.com/cardano-foundation/CIPs/issues/836) — "CIP-0013: Current state of integration and further advancements". The running thread on URI support, open since 2024-06. The tracker's handover was posted there on 2026-11-21.
- [CPS-0016](https://github.com/cardano-foundation/CIPs/tree/master/CPS-0016) — the problem statement every URI CIP lists under `Solution To`.
- CIP editors' biweekly meeting, where URI items are raised: `hackmd.io/@cip-editors`.

## How a cell is decided

The statuses and the evidence rule are in [CONTRIBUTING.md](../CONTRIBUTING.md#wallet-support-self-report). On top of that:

- **Test the link the spec defines**, character for character, on the wallet's current store release. A wallet that accepts a different shape of the same feature is not `supported` for that column.
- **Record the wallet version, OS and date** with the result, in the PR or issue that changes the cell. Per-cell provenance in the data itself is #8.
- **Amounts are the most common failure.** Test a decimal ADA amount (e.g. `?amount=1.25`) on every default-link test; mishandled decimals shipped in more than one wallet.
- **Source reading and self-reports** can move a cell to `untested` or flag it for re-test; only a test or the wallet team's own report moves it to `supported`, `partial` or `none` — except where the source shows no handler exists at all, as with Daedalus.
